# Memory Management Basics

### Logical vs Physical Address Space
-   **Logical Address (Virtual Address):** Generated by the CPU. User views the process in this space.
-   **Physical Address:** Actual location in the main memory (RAM).
-   **MMU (Memory Management Unit):** Hardware that maps Logical Address to Physical Address at runtime.

### Protection
OS uses **Base (Relocation)** and **Limit** registers to ensure a process accesses only its legal address space.

# Allocation Techniques

### 1. Contiguous Memory Allocation
Each process is contained in a single contiguous block of memory.

-   **Fixed Partitioning:** Memory divided into fixed-size partitions.
    -   **Issue:** **Internal Fragmentation** (Process size < Partition size, wasted space inside).
-   **Dynamic Partitioning:** Partition size declared at load time.
    -   **Issue:** **External Fragmentation** (Total free space exists but is not contiguous).
    -   **Solution:** **Compaction** (Shuffling memory to merge free holes).

### Free Space Management
Algorithms to find free holes:
-   **First Fit:** First hole that is big enough. (Fast)
-   **Best Fit:** Smallest hole that is big enough. (Reduces internal fragmentation, but creates tiny holes).
-   **Worst Fit:** Largest hole.

### 2. Non-Contiguous Allocation
-   **Paging:** Divide memory into fixed-size blocks.
-   **Segmentation:** Divide memory into variable-size segments based on user view (e.g., Code, Stack, Heap).

# Paging

-   **Frames:** Physical memory divided into fixed-sized blocks.
-   **Pages:** Logical memory divided into blocks of the same size.
-   **Page Table:** Data structure mapping Page Number (p) to Frame Number (f).

**Address Translation:**
Logical Address = `(Page Number p, Offset d)`
Physical Address = `(Frame Number f * Frame Size) + Offset d`

### TLB (Translation Look-aside Buffer)
A hardware cache to speed up address translation. Stores recent Page -> Frame mappings to avoid accessing the Page Table in main memory.

# Virtual Memory

Allows execution of processes that are not completely in memory. Gives the illusion of a very large main memory.

### Demand Paging
-   Pages are loaded into memory only when they are needed (Lazy Swapper).
-   **Page Fault:** Occurs when a process accesses a page that is not in memory (Invalid bit).

**Page Fault Handling:**
1.  Trap to OS.
2.  Check if reference is valid.
3.  Find a free frame.
4.  Read page from disk (Swap space) to frame.
5.  Update Page Table.
6.  Restart instruction.

# Page Replacement Algorithms

When memory is full, OS must replace an existing page to bring in a new one.

### 1. FIFO (First-In First-Out)
-   Replace the oldest page.
-   **Belady's Anomaly:** More frames can sometimes lead to *more* page faults.

### 2. Optimal Page Replacement
-   Replace the page that will not be used for the longest period of time.
-   **Best possible performance**, but impossible to implement (requires future knowledge). Used for benchmarking.

### 3. LRU (Least Recently Used)
-   Replace the page that has not been used for the longest time.
-   Approximation of Optimal. Implemented using Stack or Counters.

# Thrashing

A situation where the system spends more time paging (swapping pages in/out) than executing processes.
-   **Cause:** Degree of multi-programming is too high; processes don't have enough frames for their **Working Set** (current locality).
-   **Solution:** Decrease degree of multi-programming or use Working Set Model to allocate sufficient frames.
